Section 4: Session State & Cart Integration

How wizard data persists across steps and flows into checkout

Session Data Shape — app/lib/custom-token-session.ts
// Stored in Hydrogen session under 'customToken' key.
// Each wizard step reads/writes specific fields.
// Cleared on successful cart add.

export interface CustomTokenSession {
  // Path selection
  path: 'we-design' | 'you-design';

  // Shared fields (both paths)
  material?: 'brass' | 'color';
  variantId?: string;         // Shopify variant GID

  // "We Design" fields
  occasion?: string;           // 'milestone' | 'memorial' | 'gift' | 'organization'
  description?: string;        // Free text design description
  inspirationImageUrls?: string[];  // Shopify file URLs (up to 5)
  engraving?: {
    name?: string;
    years?: string;
    cleanDate?: string;
    note?: string;
  };

  // "You Design" fields
  designPrompt?: string;       // Customer's design description
  referenceImageUrls?: string[];   // Optional reference uploads
  previewImageUrls?: string[];    // AI-generated preview URLs
  selectedPreviewUrl?: string;    // Customer's chosen design
  refinementHistory?: {            // Refinement rounds (max 3)
    prompt: string;
    resultUrl: string;
  }[];
  finalDesignUrl?: string;      // Final approved design (Shopify file URL)

  // Metadata
  generationCount?: number;    // Track for rate limiting
  startedAt?: string;          // ISO timestamp
}

// Helper functions
export function getCustomTokenSession(session: AppSession): CustomTokenSession | null;
export function updateCustomTokenSession(session: AppSession, data: Partial<CustomTokenSession>): void;
export function clearCustomTokenSession(session: AppSession): void;
export function getCompletedSteps(session: CustomTokenSession): string[];
export function canProceedToStep(session: CustomTokenSession, step: string): boolean;
Session Lifecycle
1. Created
User picks "We Design" or "You Design" on landing page. Session initialized with path and startedAt.
→
2. Progressive Fill
Each step's action validates input, writes to session, redirects to next step. Layout route reads session for progress bar.
→
3. Step Guards
Each step's loader checks canProceedToStep(). If prerequisite steps aren't complete, redirects back. Prevents URL jumping.
→
4. Cleared
On successful cart add, session is cleared. If user abandons wizard, session expires naturally with the Hydrogen session TTL.

Pattern match: This follows the same approach as existing engraving data — line item attributes with underscore-prefixed private keys. The Klaviyo notification is fire-and-forget (same as the existing circle-add pattern), so it doesn't block the cart add. The admin sees public attributes in the order view, and the Klaviyo email provides a formatted design brief with clickable image links.
